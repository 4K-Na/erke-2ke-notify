## 三、需要处理的问题

### P1-1　Tomcat 线程数过高，突发流量会导致内存耗尽

```
tomcat.threads.max      = 800
tomcat.accept-count     = 1000
物理内存                = 1612MB（当前可用 573MB）
```

800 个线程每个约占 1MB 栈空间，满负荷运行时单是线程栈就吃掉 800MB，叠加 JVM 堆和 MySQL 会直接 OOM。这台机器的实际并发承受力在 **50～100** 之间。

建议改为 `threads.max=200`、`accept-count=100`，超出的请求排队而不是开线程。

### P1-2　三个与本项目无关的端口暴露在公网

| 端口 | 用途 | 风险 |
|---|---|---|
| `7000` | frps 控制端口 | frp 服务端管理口，暴露可被尝试爆破 token |
| `61986` | BeEF WebSocket（SSL） | 遗留项目，当前无业务需要 |
| `39198` | Minecraft 服务器 TCP 代理 | 游戏服，与本项目无关 |

这三个如果还要用，建议在阿里云安全组里限定来源 IP；不用的话直接关闭。

### P1-3　公开接口没有限流

```
连续 60 次请求 → 60 个 200，无一个 429
100 并发     → 全部 200，总耗时 7.9 秒
```

`/system/tnotice/public/list` 是订阅页和公告页用的匿名接口，无限流意味着可以被脚本反复刷。虽然只读、单次查询很快，但持续压会挤占后端资源。建议给这个路径加 `limit_req`（例如 30 次/分钟/IP）。

### P2-1　两个入口缺少安全响应头

```
https://example.com/      HSTS、X-Frame-Options、X-Content-Type-Options、CSP 全缺
http://<SERVER_IP>:18089/   同上全缺
```

订阅页是静态资源，风险较低；18089 是管理后台的明文入口，缺 `X-Frame-Options` 意味着可以被嵌入 iframe 做点击劫持。建议在 nginx 层统一补上。

### P2-2　18089 明文 HTTP 仍在服务

管理后台用它输入密码，全程明文传输。既然 18443 已经可用（证书正常），建议把 18089 改成 301 跳转到 18443。

### P2-3　证书 89 天后到期

当前证书 `CN=example.com`，有效期至 2027-02-06。certbot 自动续期任务在跑，但需要确认续期后 nginx 会自动 reload。

## 四、建议动作顺序

1. **降 Tomcat 线程数**（改配置重启，5 分钟）—— 这是用户变多后最直接的风险
2. **关掉 7000 / 61986 / 39198**（安全组或 nginx，5 分钟）
3. **公开接口加限流**（nginx 配置，10 分钟）
4. **补安全响应头 + 18089 跳转**（nginx 配置，10 分钟）
5. 证书续期机制复核（10 分钟）

前两项做完，这台机器应对"用户变多"的余量就足够了。
