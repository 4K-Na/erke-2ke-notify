## 发现的问题

### P0

#### P0-1　443 的默认 server 被 `beef.example.com` 接管，公网凭 IP 可直连摄像头直播页与检测 API

**描述**：`/etc/nginx/conf.d/dsh-tunnel.conf` 里的 `beef.example.com` 块（`listen 443 ssl http2`）在配置加载顺序上排在 `sites-enabled/example.com` 之前，且没有别的 443 块声明 `default_server`，于是它成了 443 的隐式默认站点。任何 Host 不匹配的 443 请求都落到这个块。

**证据**（服务器本机回环，模拟不同 Host）：

```
Host=example.com      GET /  -> HTTP=200
Host=beef.example.com GET /  -> HTTP=502
Host=nobody.invalid      GET /  -> HTTP=502      ← 默认落这里
Host=<SERVER_IP>        GET /  -> HTTP=502      ← 默认落这里

Host=beef.example.com /        -> 502
Host=beef.example.com /files/  -> 502
Host=beef.example.com /detect/ -> 200
Host=beef.example.com /cam/    -> 200
Host=beef.example.com /cam.html-> 200
```

**从公网（本机发起，不带任何域名）**：

```
https://<SERVER_IP>/cam.html  HTTP=200 size=7750
https://<SERVER_IP>/detect/   HTTP=200 size=15
https://<SERVER_IP>/cam/      HTTP=200 size=5967
https://<SERVER_IP>/          HTTP=502

cam.html 正文：<!doctype html><html lang="zh-CN"><head>…<title>摄像头直播</title>…
/detect/ 正文：{"history": []}
```

`/etc/nginx/conf.d/dsh-tunnel.conf` 原文：

```nginx
server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name beef.example.com;
    ssl_certificate /etc/letsencrypt/live/beef.example.com/fullchain.pem;
    ...
    location /files/  { proxy_pass http://127.0.0.1:8000/; }
    location /detect/ { proxy_pass http://127.0.0.1:8099/; }
    location = /cam.html { root /var/www/cam; }
    location /cam/    { proxy_pass http://127.0.0.1:8088; }
    location /        { proxy_pass http://127.0.0.1:7080; ... }
}
```

**影响**：
1. **隐私**：任何人不带域名、只凭 `<SERVER_IP>` 就能打开「摄像头直播」页面（7.7 KB 页面指向 `mediamtx` 的 8088 流），并读取 `/detect/` 的人脸/检测历史接口。这不是第二课堂的数据，但它在同一台机器、同一个 443 上，暴露面等于第二课堂的暴露面。
2. **可用性 / 品牌**：`https://<SERVER_IP>/` 返回 502 而不是订阅页；而 80 端口 `http://<SERVER_IP>/` 正常。学生用 IP 访问会看到 502。
3. 默认站点是一个**攻击框架**（`/opt/beef-0.6.0.0`，BeEF），即使 7080 没监听，配置仍在生效。

**建议修法**：把 `dsh-tunnel.conf` 从 `conf.d/` 移出（或加 `server_name` 白名单后置于 `sites-enabled` 之后），并给 443 明确指定一个无害的 default_server 统一 `return 444;`；`beef`/`mediamtx` 若已不用，一并下线。**改动涉及别的项目，需用户决策。**

#### P1-2　SSH 允许 root 密码登录，且开着 `GatewayPorts yes`、会话上限被放到 64

**证据**：

```
$ sshd -T | grep -E "permitrootlogin|passwordauthentication|maxauthtries|port"

maxauthtries 6
permitrootlogin yes
passwordauthentication yes

$ grep -v -E "^\s*#|^\s*$" /etc/ssh/sshd_config
Include /etc/ssh/sshd_config.d/*.conf
PubkeyAuthentication yes
KbdInteractiveAuthentication no
UsePAM yes
GatewayPorts yes                     ← 远程端口转发可绑 0.0.0.0
X11Forwarding yes
PermitRootLogin yes
PasswordAuthentication yes
AuthorizedKeysCommand /usr/bin/ecs_config_instance_connect --uid %U
...

$ cat /etc/ssh/sshd_config.d/99-codex-stability.conf
MaxStartups 100:30:200
MaxSessions 64
ClientAliveCountMax 99999
PasswordAuthentication yes
PermitRootLogin yes
```

**影响**：root + 密码 + 公网 22 = 可被离线爆破的组合（当前密码 14 位字母数字，强度尚可，但一旦泄露即 root）；`GatewayPorts yes` 让任何拿到账号的人可以把服务器当跳板，把任意内网端口反代到公网；`MaxSessions 64` / `ClientAliveCountMax 99999` 放大了资源占用。

fail2ban 在护（`sshd` 单 jail，`_COMM=sshd`，5 次/10 分/封 1 小时），实测有效：

```
Status for the jail: sshd
|- Currently failed: 5
|- Total failed:     6035
`- Currently banned: 1
   `- Banned IP list: 203.17.87.55
```

但 24 小时 `-p err` 里 49 条全是 `kex_exchange_identification: read: Connection reset by peer`（互联网背景扫描），说明 22 一直在被扫。

**建议修法**（需用户决策，涉及锁门外风险）：① 关 `PasswordAuthentication`，只留公钥（`authorized_keys` 现有 2 条，`root@lzywindowsssss` + `lzy@DESKTOP-EIFIQ8J`）；② `GatewayPorts no`；③ 恢复默认 `MaxSessions 10` / `ClientAliveCountMax 3`；④ 若要保留密码登录，至少加 `AllowUsers root`。**建议改前先在控制台开 VNC/Workbench 兜底。**
